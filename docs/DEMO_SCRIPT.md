# Viva demo script (10 minutes)

| Minutes | What | Notes |
| --- | --- | --- |
| 0-2 | Problem and gap | One slide; say what existing tools do not do |
| 2-4 | Architecture | The loop diagram; stop on the lookup table |
| 4-7 | Live demo, three turns | Below |
| 7-9 | Evidence | Agreement with interval, response review, pilot, comparison if done |
| 9-10 | Limits and next steps | Say them yourself first |

## Demo arguments (rehearse with the frozen prompts and the real model)
1. "Social media should be banned for children because it is harmful." Expect a request for evidence or a warrant.
2. Add support. Use a real, checkable source you have verified; if you use a made-up example, say aloud that it is a placeholder.
3. Add a response to critics, for example that bans are hard to enforce but age checks already work elsewhere.
Show after each turn: the scores, the diagnosed weakness, the strategy line, the opponent reply, and the progress panel.

## Be straight about what the demo is
A demo shows how the system works. It is not evidence that it works; the evidence is the evaluation. If you pick the cleanest of several rehearsals, say that you did.

## Before the day
- [ ] Rehearse five times; note which weaknesses appear.
- [ ] Record a two-minute screen video; keep copies on two devices.
- [ ] Warm up the model or API 10 minutes before; check the key and quota.
- [ ] Keep the database and `results_summary.md` open in case the panel asks for the data behind a number.

## If it fails live
Say so calmly and switch to the recording. Never switch silently to the `heuristic` backend: it is a rule-based stand-in, not your system.
